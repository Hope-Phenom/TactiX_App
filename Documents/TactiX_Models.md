# TactiX_Models

## 项目概述

TactiX_Models 是 TactiX_App 的数据模型项目，包含了应用程序的核心数据结构、消息总线、网络模型和战术模型等。

## 目录结构

```
TactiX_Models/
├── MessageBus/              # 消息总线模型
├── Network/                 # 网络模型
├── Tactics/                 # 战术模型
├── L_Config.cs              # 配置模型
├── L_HotkeyBinding.cs       # 热键绑定模型
└── TactiX_Models.csproj     # 项目文件
```

## 主要功能

- 定义应用程序的核心数据结构
- 提供消息总线功能，实现组件间通信
- 定义网络请求和响应模型
- 定义战术相关的数据模型
- 提供配置和热键绑定模型

## 核心模块

### 消息总线 (MessageBus)

消息总线用于实现应用程序各组件之间的通信，包含多种消息类型：

- **导航消息** - 用于页面导航
- **窗口消息** - 用于窗口管理
- **热键消息** - 用于热键处理
- **吐司消息** - 用于显示提示信息
- **文件对话框消息** - 用于文件选择

### 网络模型 (Network)

定义了网络请求和响应的数据模型：

- **版本控制** - 用于检查应用版本
- **新闻** - 用于获取新闻信息
- **论坛主题** - 用于获取论坛主题
- **视频信息** - 用于获取视频信息
- **异常报告** - 用于报告应用异常

### 战术模型 (Tactics)

定义了战术相关的数据模型：

- **战术 (L_Tactic)** - 表示一个完整的战术
- **战术动作 (L_TacticAction)** - 表示战术中的一个动作
- **回放动作 (L_ReplayAction)** - 表示回放中的一个动作
- **战术枚举 (L_TacticEnum)** - 定义战术相关的枚举类型
- **模组项 (L_ModItem)** - 表示模组项
- **模组描述 (L_ModDesc)** - 表示模组描述

### 配置模型 (L_Config)

定义了应用程序的配置数据结构，用于保存应用程序的设置。

### 热键绑定模型 (L_HotkeyBinding)

定义了热键绑定的数据结构，用于保存用户的热键设置。

## 开发指南

### 使用消息总线

1. 注入消息总线服务
2. 订阅感兴趣的消息类型
3. 发布消息

### 添加新的消息类型

1. 在 `MessageBus/` 目录下创建新的消息类
2. 消息类应遵循命名规范：`MB_{MessageName}.cs`
3. 确保消息类包含必要的属性和方法

### 添加新的网络模型

1. 在 `Network/` 目录下创建新的网络模型类
2. 网络模型类应遵循命名规范：`N_{ModelName}.cs`
3. 确保模型类包含必要的属性和序列化/反序列化支持

### 添加新的战术模型

1. 在 `Tactics/` 目录下创建新的战术模型类
2. 战术模型类应遵循命名规范：`L_{ModelName}.cs`
3. 确保模型类包含必要的属性和方法

## 注意事项

1. 模型类应保持简洁，只包含数据和必要的方法
2. 模型类应支持序列化和反序列化
3. 模型类的命名应遵循项目的命名规范
4. 避免在模型类中包含复杂的业务逻辑
5. 模型类应具有良好的可扩展性
